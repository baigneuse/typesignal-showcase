# TypeSignal

一个围绕“为什么重复测验会在相邻人格类型之间变化”设计的多语言测量产品，让用户看到四字母标签背后的倾向、接近程度与历史变化。

[正式产品](https://typesignal.app) · [English](README.md) · [日本語](README.ja.md) · [系统架构](docs/architecture.md)

**这是面向招聘与技术评审的脱敏工程和产品案例，不是商业产品的开源版本。**

## 产品问题

`INTP → INTJ → INTP`。只返回标签，无法说明变化发生在哪个维度、结果是否接近分类边界、两次测验是否具备可比性。

TypeSignal 把测量、解释和历史比较作为同一产品问题处理：保留维度倾向，解释接近的候选类型，允许用户回看可比较记录之间的差异。它是自我反思工具，不是临床评估，也不是官方 MBTI 测验。

## 公开证据

- 类型标签与维度分值分离的简化领域接口。
- 模型、问卷、语言和时间兼容性验证。
- 基于三次合成记录的差分计算与可追溯说明。
- locale 与 market 独立的类型和校验代码。
- 无效输入、不可比较情况与语言／市场独立性的测试。
- 公开边界检查、Git 历史扫描与持续集成。

合成示例中，T1 到 T2 的 J–P 数值从54降为48。在这个示例尺度里，这表示向J侧移动6点；S–N只移动1点，T–F不变。INTP／INTJ标签由示例直接提供，公开代码不负责计算它们，也不会从这些差分推断真实人格变化或心理原因。

## 多语言不等于多市场

语言包括 `ja / zh-Hans / zh-Hant / en`；市场包括 `JP / TW / HK / GLOBAL_ZH / GLOBAL_EN`。语言决定呈现，市场承载商业与地区语境，部署承载基础设施环境。繁体中文不能自动等同台湾，日文界面也不能自动决定购买市场。

## 快速评审

先阅读[英文README](README.md)，再用Node.js 24运行：

```sh
npm ci --ignore-scripts
npm run verify
npm run demo
```

之后查看[比较实现](src/comparison.ts)、对应测试、[测量设计](docs/measurement-design.md)与[脱敏边界](docs/sanitization.md)。无需环境变量或生产服务；安装依赖后，示例可离线运行。
