# TypeSignal

性格診断の結果が近いタイプの間で変わるとき、4文字だけでは見えない傾向の違いを説明する、多言語のプロダクトです。

[公開中のプロダクト](https://typesignal.app/ja) · [English](README.md) · [中文](README.zh-CN.md) · [アーキテクチャ](docs/architecture.md)

**このリポジトリは、採用選考や技術レビュー向けに公開範囲を限定したケーススタディです。商用プロダクトのソースコード全体を公開するものではありません。**

## 取り組んだ課題

`INTP → INTJ → INTP`。診断を受け直してタイプ名が変わっても、その理由が結果画面から読み取れないことがあります。TypeSignalでは、各軸の傾向、近いタイプ、過去の結果との違いを一緒に見られるようにしています。

ここで示すのは、課題の整理から測定モデル、説明、履歴比較、多言語・市場設計、商用サービスとしての提供までをつなぐ設計判断です。医療上の診断や、公式のMBTI検査を提供するものではありません。

## このリポジトリで確認できること

- タイプ名と各軸の得点を分けた、簡略化したデータモデル。
- モデル・質問セット・言語が異なる記録を、そのまま比較しない検証処理。
- 架空の3回分の記録を使った差分計算と、数値に基づく説明。
- 表示言語と市場を独立した型として扱う実装。
- 不正な入力や比較できない条件を含むテスト、公開前のチェック、CI。

例のT1とT2では、J–Pの値が54から48に動きます。この尺度では小さいほどJ側なので、6ポイントJ側に動いたと説明できます。併記したINTP／INTJは例のために用意したラベルであり、公開コードが算出した診断結果ではありません。変化の原因や、その心理学的な意味も断定しません。

## 言語と市場は別の選択

表示言語は `ja / zh-Hans / zh-Hant / en`、市場は `JP / TW / HK / GLOBAL_ZH / GLOBAL_EN` として扱います。繁体字を選んだからといって台湾に決めつけたり、日本語表示だから日本向けの購入条件を適用したりしない設計です。

## 10分で確認するなら

1. [英語README](README.md)で全体像を確認。
2. Node.js 24で以下を実行。
3. [比較処理](src/comparison.ts)とテストを読む。
4. [測定モデルの考え方](docs/measurement-design.md)と[公開範囲](docs/sanitization.md)を確認。

```sh
npm ci --ignore-scripts
npm run verify
npm run demo
```

環境変数やデータベース接続は不要です。依存パッケージの取得後、サンプルはオフラインで動きます。
